How these explainers are made

This is the brief I give my AI assistant for every explainer on this site. It is the same each time.

The original request

"Explain this hyper intuitively, bottoms up, with the most simple step by step animations so I really understand concretely."

Then: "share a html". The result is one self-contained web page you can open anywhere.

The bottom-up rule

  • Start with the smallest working piece, such as a model on its own or a single tool.
  • Add one idea per step.
  • Open each step with the problem the last step left behind.
  • Put the whole picture together near the end. Then cover attacks and failure cases, cost, what is proven, what is not yet, and what each audience takes away.
  • If two steps can swap places, it is a list and not a build. Reorder until each step needs the one before it.

How the page is built

  1. Gather facts from primary sources only: documentation, evidence, code. Mark preview features, made-up data and my own reading. Invent no numbers. Say how any measured figure was measured.
  2. Outline 12 to 18 steps. Each step answers one question.
  3. For each step, draw one small animation. It plays in beats, one idea per beat.
  4. Under each beat, write a plain explanation.
  5. Next to it, put a red "Say this" box with the exact words to speak.
  6. Add a short panel that tailors the point for an executive, a security reader and an operations reader.
  7. End with a quiz of six to eight questions.
  8. Open every step in a browser and look for overflow, overlap and clipped text before it goes out.

The Say box is a story, not a caption

  • Each step tells one small story across its beats: a generic person or agent, one want, one thing that goes wrong, one fix.
  • Never a named character.
  • The product or exam term arrives last, as the name for what just happened. The listener should be able to repeat it to someone else.
  • End each step with one plain line to carry away.
  • Few words. Each beat moves the story one step.

Voice

  • Short plain sentences. "I" and not "we". No em dashes. No emoji.
  • No "not this but that" contrast tricks.
  • Teach from zero. Plain word first, then the proper term. Never an unexplained acronym.
  • Fictional data only in examples and labs.

The assistant follows this brief closely. It can still get facts wrong, so check anything that matters against the source linked in each explainer.
